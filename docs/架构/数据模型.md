# 数据模型

**Nexus 是业务状态的唯一归属方。** Scout 不访问 Nexus 数据库；渠道消息真源在 Scout 本地。

`mino.db`（SQLite），表定义在 `models/*.py`，一张表一个文件。**改字段必须同步本文**。

## 1. 库文件与路径

| 环境 | 数据根 | 库文件 |
|---|---|---|
| 开发（`--dev`） | `~/.mino-dev/nexus/`（可用 `MINO_NEXUS_DEV_DATA_DIR` 覆盖） | `mino.db` |
| 正式（`--prod` / `service`） | `~/.mino/nexus/`（可用 `MINO_NEXUS_DATA_DIR` 覆盖） | `mino.db` |
| Docker | `/data` | `mino.db` |

开发与正式**禁止共用或互相包含目录**，启动时校验环境标记。旧安装目录不自动迁移。

## 3. 写库纪律

- **禁止在调试时直接对 `mino.db` 增删改。** 用接口或会话写入。
- 迁移前用 SQLite backup API 生成一致备份（0600），不覆盖旧备份。
- 历史无 owner 的节点认领在单个事务内同时更新 `nodes`、未归属 `m_device` 与 `node_credentials`。
- 业务状态进 sqlite。**禁止再给项目 / 应用 / 设备 / 跑批 / 账号 / 设置 / 能力目录加 JSON 真源。**

## 4. 项目需求目录

项目需求以 `(project_id, requirement_id)` 标识，适用应用使用 `app_ids`（空列表表示项目通用），可保存需求文档 `source_url` 和用例文档 `cases_url`。历史 `app_id` 作为单元素范围兼容，返回的 `app_id` 只在单应用时非空。

`requirement_update` / `PUT /project/{project_id}/requirements/{requirement_id}` 支持部分更新、`new_requirement_id` 改名及多应用范围；校验项目归属、应用归属和 ID 重名。Python 在同一事务内更新各应用的既有需求配置及用例需求引用，列表按 ID 合并应用范围。历史执行快照不改写，脚本仓目录由调用方另行改名并 push。


### Web 资源恢复决定

恢复决定保存在 ScoutRecord.context.resource_resolution 与 AppRegressionRun.payload.resource_resolution，绑定 owner、原 Scout/SN、租约代次、停止证明和摘要版本。停止证明通过后，任务投影和设备/账号/准入释放在同一事务提交，不覆盖原封存摘要。

## 账号数据记忆

Python additive migration 建立账号数据表，不改共享库进行调试。保留 SQLite SQL 真源，不新增另一套数据库。账号删除同时清理记忆，账号环境从父账号获取。对象记忆可以在账号被租用期间更新，不改身份、业务标签或租约。只存引用及少量特征，不存凭据、完整文件、DOM 或页面句柄；data_id 是账号内稳定标识，save 为整条更新。申请需求只留描述，既不自动生成业务数据，也不产生分配门禁。

Agent 进度使用 `agent_workflows`，Python schema 12。state 保存 scope、单位、预算、尝试与核对历史，单记录限制 2MB。Python 用 BEGIN IMMEDIATE 原子占预算；未确认更新返回 409，Agent 先读原 attempt。登录用户决定归属，请求体不能改变 owner。阶段完成不等于业务验证通过，既不自动执行，也不是 Nexus 用例准入条件。

## 账号生效应用（2026-11-18）

Python schema 13 对 `pool_accounts` 追加非空 JSON `app_ids`，追加前通过 SQLite backup API 生成同目录下不覆盖旧文件的 0600 备份。接口返回 `app_ids: string[]`。新账号与显式更新必须至少包含一个当前项目应用，最多 100 项，去重保存；历史 `[]` 仅表示未关联应用，不再代表全部应用。部分更新和业务状态写回保留范围，占用期间禁止修改范围。自动补号绑定本次目标应用。

账号列表可展示保存范围；按应用的列表、详情、选号、候选排序、模板分配、恢复与实际租约领取都要求显式 `app_id` 并按范围过滤。Python 原子领取在事务内复核当前 `app_ids`，防止使用过期范围。范围与环境、登录身份及租约状态共同生效，业务数据偏好不能放宽范围；历史空范围账号不可通过省略应用绕过检查。

测试账号的 `password` / `otp` 使用字段级 AES-GCM 密文存储，主密钥不进入数据库；当前仍是单机 SQLite 和部署级 keyring。业务测试账号唯一真源是 Nexus 号池，当前不建设 KMS、第二套账号表或多实例密钥体系；边界见[凭据存储边界](凭据存储与多机部署.md)。
