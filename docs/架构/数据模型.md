# 数据模型

**Nexus 是业务状态的唯一归属方。** Scout 不访问 Nexus 数据库；渠道消息真源在 Scout 本地。

`mino.db`（SQLite），表定义在 `models/*.py`，一张表一个文件。**改字段必须同步本文**。

## 1. 库文件与路径

| 环境 | 数据根 | 库文件 |
|---|---|---|
| 开发（`--dev`） | `~/.mino-dev/nexus/`（可用 `MINO_NEXUS_DEV_DATA_DIR` 覆盖） | `mino.db` |
| 正式（`--prod` / `service`） | `~/.mino/nexus/`（可用 `MINO_NEXUS_DATA_DIR` 覆盖） | `mino.db` |
| Docker | `/data` | `mino.db` |

开发与正式**禁止共用或互相包含目录**，启动时校验环境标记。旧安装目录不自动迁移。

## 3. 写库纪律

- **禁止在调试时直接对 `mino.db` 增删改。** 用接口或会话写入。
- 迁移前用 SQLite backup API 生成一致备份（0600），不覆盖旧备份。
- 历史无 owner 的节点认领在单个事务内同时更新 `nodes`、未归属 `m_device` 与 `node_credentials`。
- 业务状态进 sqlite。**禁止再给项目 / 应用 / 设备 / 跑批 / 账号 / 设置 / 能力目录加 JSON 真源。**

## 4. Cloudflare 部署的持久执行表

Cloudflare 与 Python 采用相同业务契约，存储适配使用 D1。`0012_scout_records_dispatch.sql` 新增：

| 表 / 字段 | 内容 |
|---|---|
| `scouts.record_api_version` | Scout 显式声明的本地记录 API 能力，当前为 1 |
| `script_dispatches` | 每个 attempt 的持久派发、请求快照、节点/用户归属、摘要版本、结果索引、重试时间；不存完整事件 |
| `script_device_leases` | 设备或 Web 槽位的持有者、lease ID、递增代次和 held/unknown/isolated/released 状态 |
| `script_request_keys` | 用户请求幂等键与任务身份 |
| `pool_accounts` | 项目/用户/环境归属、账号凭据、标签、锁定状态与任务租约 |
| `app_regression_runs.payload_json` | 任务及每例结果索引，含 `record_source=scout`、记录节点、summary_version、水位、覆盖与断言计数 |
| `app_regression_run_stats` | 应用级任务计数与最新任务指针；`0019_reduce_run_reads.sql` 回填并由任务插入、状态更新、删除触发器维护，任务明细仍只以 `app_regression_runs` 为真源 |

完整记录和 artifact 真源在 Scout 本机；Nexus 的状态索引用于调度与离线摘要，不代替证据。摘要更新使用单调版本和比较交换，取消意图独立保留。未知结果不会因租约时钟经过而自动释放。

项目环境配置复用 D1 `user_settings`，键为 `project.env:<project_id>`，按 `owner_user_id` 隔离。GET/PUT 均校验项目归属，PUT 在保存成功后返回确认；局部更新合并已保存字段，比较交换防止并发更新覆盖。账号凭据仍使用 `pool_accounts`，环境接口拒绝内嵌 `test_accounts`。

## 5. 项目需求目录

Cloudflare `project_requirements` 的主键为 `(project_id, requirement_id)`。`0013_requirement_scope.sql` 增加 `app_ids_json`（适用应用 ID 列表，空列表表示项目通用）和 `cases_url`（用例文档）；`source_url` 保存需求文档。历史 `app_id` 迁移为单元素列表，返回的 `app_id` 只在单应用时非空。

`requirement_update` / `PUT /project/{project_id}/requirements/{requirement_id}` 支持部分更新、`new_requirement_id` 改名及多应用范围；校验项目归属、应用归属和 ID 重名。Python 在同一事务内更新各应用的既有需求配置及用例需求引用，列表按 ID 合并应用范围。Cloudflare 使用条件更新防止覆盖并发修改。历史执行快照不改写，脚本仓目录由调用方另行改名并 push。


### Web 资源恢复决定

Cloudflare 迁移 `0015_resource_resolutions.sql` 增加 `script_resource_resolutions`：run_id 唯一，绑定 owner、原 Scout/SN、lease_id/generation、各 attempt 的停止证明与摘要版本、恢复时间。停止证明、任务投影和设备/账号/准入释放在同一 D1 batch 提交；不覆盖原封存摘要。Python 在 ScoutRecord.context.resource_resolution 与 AppRegressionRun.payload.resource_resolution 保存等价恢复决定，在同一事务释放执行资源、账号租约、设备租约和预约。

## 账号数据记忆

Cloudflare 应用 `0016_account_data.sql` 后上线；Python additive migration 建立账号数据表，不改共享库进行调试。保留现有 D1/SQLite SQL 真源，不新增另一套数据库。账号删除同时清理记忆，账号环境从父账号获取。对象记忆可以在账号被租用期间更新，不改身份、业务标签或租约。只存引用及少量特征，不存凭据、完整文件、DOM 或页面句柄；data_id 是账号内稳定标识，save 为整条更新。申请需求只留描述，既不自动生成业务数据，也不产生分配门禁。

Agent 进度使用 `agent_workflows`，Cloudflare migration `0017_agent_workflows.sql`、Python schema 12。state 保存 scope、单位、预算、尝试与核对历史，单记录限制 2MB。Python 用 BEGIN IMMEDIATE 原子占预算；CF 用 revision CAS 并有限重试，未确认更新返回 409，Agent 先读原 attempt。登录用户决定归属，请求体不能改变 owner。阶段完成不等于业务验证通过，既不自动执行，也不是 Nexus 用例准入条件。

## 账号生效应用（2026-11-18）

Python schema 13 对 `pool_accounts` 追加非空 JSON `app_ids`，追加前通过 SQLite backup API 生成同目录下不覆盖旧文件的 0600 备份；Cloudflare `0018_account_app_scope.sql` 追加 TEXT `app_ids_json`。两端对外返回相同的 `app_ids: string[]`。默认 `[]` 表示项目全部应用，保留历史账号范围；指定范围须为当前项目应用，最多 100 项，去重后保存。部分更新和业务状态写回保留范围，占用期间禁止修改范围。自动补号绑定本次目标应用。

账号列表展示保存范围；指定应用的选号、候选排序、模板分配、恢复与实际租约领取按范围过滤。Python 原子领取在事务内复核当前 `app_ids`，Cloudflare 领取以 `app_ids_json` 比较交换防止使用过期范围。范围与环境、登录身份及租约状态共同生效，业务数据偏好不能放宽范围。省略目标应用的租号只允许项目通用账号。
