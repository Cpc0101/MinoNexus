# 执行链

一次用例从 `case_run` 到写入 `session_events` 的完整路径。**执行在 Scout，Nexus 只做准入、下发、落账。**

```
用例 / agent
   │ case_run
   ▼
Nexus 准入（设备占用 · 账号租约 · 写安全 · 仓库已配置）
   │ script.run 载荷（仓库地址 / 提交 / 脚本路径 / sn / platform）
   ▼
Scout 调度接口（核 run_id·sn·渠道程序就绪）
   │ git clone → 读 config.yaml → 执行 tests/**/<case_id>.py 的 run(case)
   ▼
Scout 脚本执行（设备动词本机；账号 / 步骤 / 失败 / 证据回调）
   │ script.callback
   ▼
Nexus 写入 session_events（tool/result、node/enter、node/leave、截图引用）
```

## 1. 准入（Nexus，`loop/script_dispatch.py`）

依次检查，任一失败则**不下发**，原因写进任务：

| 检查 | 失败 reason_code |
|---|---|
| 项目已配置脚本仓库 | `script_repo_missing` |
| 用例归属项目一致 | `project_scope_invalid` |
| 设备在线且被本节点持有 | `node_offline` |
| 账号租约 / 设备资源 / 写安全 | 见 [资源与租约](../专题/用例密钥与租约.md) |
| 会话可写（`open_session`） | `SessionPersistenceError.reason_code` |

准入通过后打开会话（`session_id` 规则不变），注册一份 `ScriptAdmission`（run_id / session_id / sn / node_id / owner_user_id / writer），然后把载荷发给持有该 `sn` 的 Scout。

## 2. 下发载荷（`script.run`）

`core/protocol.py: SCRIPT_RUN_FIELDS` 定义 9 个字段，**没有 `files`、没有 `version`**：

| 字段 | 含义 |
|---|---|
| `run_id` | Nexus 准入的任务号 |
| `session_id` | 写入 `session_events` 的会话 |
| `case_id` | 用例 id |
| `sn` | 本趟设备 |
| `platform` | `android` / `ios` / `web` / `mac` / `win` |
| `repo_url` | 项目脚本仓库地址，已去掉内嵌凭据 |
| `branch` | 分支，可空 |
| `revision` | 提交，可空（空 = 分支最新） |
| `script_path` | 仓库内相对 `.py`，可空（空 = 按 `tests/**/<case_id>.py` 找） |

`device_hint` 只带 **Nexus 已经知道的事实**：`env`（本次环境）、`app_id`、以及设备记录里已有的 `adb_serial` / `udid` / `model`。Scout 从这里拿不到任何绝对路径或密钥。

**约束**：`branch` / `revision` 不得以 `-` 开头、不含空白与控制字符；`script_path` 必须落在仓库内。令牌无效、`sn` 不符、节点未登记该渠道 → **整次 `declined`，不碰设备**。

## 3. Scout 侧（`server_comm/script_dispatch.py` → `runtime/script_exec.py`）

1. 核对 `run_id` 仍占用本节点本 `sn`，失败 `declined`，不创建脚本进程。
2. 渠道程序未就绪（Android 缺 adb、Web 缺 Chromium）→ `declined`，原因写明缺哪项，**不在本次运行里自动下载**。
3. 同一 `run_id` + `case_id` 重复投递 → 返回进行中，不并行第二份。
4. `git clone` 到临时目录（取 `revision`，空则分支最新），读 `config.yaml` 与脚本，运行结束删临时目录。
5. 仓库根加入 `sys.path`，入口是 `script_path` 的 `run(case)`。存在根上 `pretest.py` / `posttest.py` 时顺序为：项目前置 → 用例前置 → `run` → 用例后置 → 项目后置（后置在 `finally`）。

## 4. 回调（Scout → Nexus，`script.callback`）

Scout 用 `case._callback(op, params)` 发一次 `EXECUTE`，`capability_id=script.callback`、`params.op` 是操作名。Nexus 侧 `loop/script_callback.py` 逐项校验后处理。

| op | 谁执行 | Nexus 做什么 |
|---|---|---|
| `account` | Nexus | 按 run 恢复租约，回 `{id, email, phone, username, password, otp, login_policy}` |
| `step`（enter / leave） | Nexus | 写 `node/enter` / `node/leave`，含步骤号、角色、原文、状态 |
| `fail` | Nexus | 写一条 `tool/result`（`status=fail`、`source=script_run`），结束为 fail |
| `note` | Nexus | 只记证据（脱敏后限长），不操作设备 |
| `script.lease` | Nexus | 设备 / 账号租约续期 |
| `script.step` / `script.session` | Nexus | 证据类，直接写入动作记录 |
| 设备动词（`launch` / `tap` / `input` / `swipe` / `back` / `wait` / `screenshot` / `sample` / `hierarchy` / `on_page` / `close`） | **Scout 本机** | 不参与 |
| `llm` / `vlm` / `vlm_frame` / `otp` | **Scout 本机** | 不参与（见下） |

**校验三项**（`_require`）：`session_id` 与这次运行一致、调用方 node_id 是该设备所在节点、任务仍存活。任一不符直接 FAIL，并在日志记 `callback ... rejected`。

**未知 op 不静默**：`_call()` 里没有对应分支 → `PermissionError("Nexus 不处理这个回调")`。新增回调必须同时改 Scout 与 Nexus。

### 4.1 模型与验证码在 Scout 本机

`case.llm` / `case.vlm` 走 `server_comm/model_call.py`，用**该节点自己**保存的 base_url / model / api_key 直连 `/chat/completions`；`case.scout.otp(account)` 按账号登录策略取码：账号自带码 → 固定码 → 本节点 Gmail IMAP。**密钥与截图不回 Nexus。**

## 5. 结束

Scout 返回结果 → Nexus `_map_status` 归一为 `pass / fail / cancelled / blocked / declined / skipped` → 检查写安全（未核验的写动作收口为 `blocked` + 资源隔离）→ `writer.close(status, summary, step_count, reason_code)`。

`feed` 到 UI 的是同一份 `session_events`，Workbench 不另建轨迹格式。

## 6. 失败码对照

| 阶段 | reason_code | 含义 |
|---|---|---|
| 准入 | `script_repo_missing` | 项目还没有配置脚本仓库 |
| 准入 | `project_scope_invalid` | 用例不属于该项目 |
| 准入 | `node_offline` | 持有该设备的节点不在线 |
| 准入 | `task_cancelled` | 开跑前已取消 |
| 下发 | `script_no_result` | 节点没有返回结果 |
| 下发 | `script_dispatch_error` | 下发过程异常 |
| 收口 | `write_outcome_unknown` | 写动作未核验，设备与账号仍隔离 |
| Scout | `locator_missing` | 该渠道没有这个控件的定位单元格 |
| Scout | `control_unknown` | 页面文件里没有这个控件 |
| Scout | `model_unconfigured` | 节点没有配模型地址 / 模型名 / 密钥 |
| Scout | `otp_environment_unavailable` | 无固定码且本节点未配 Gmail 收信 |
| Scout | `revision_missing` | 取不到指定提交 |

排查入口：[Session 日志与数据库](../排查/Session日志与数据库.md) · [常见问题](../排查/常见问题.md)

## 7. 按需求直接下发

`POST /case-runner/run` 带 `script_targets` 时不读用例正文。每一项是 `requirement_id` 和可选 `case_ids`。指定了用例 ID 时，`script_path` 为 `tests/<需求ID>/<用例ID>.py`。`case_ids` 为空时，Scout 用 `script.list` 列出该目录后，仍是一条用例一条 session。原来按 `case_ids` 从用例库展开的路径保持不变。
