# 执行链

Python Nexus 是唯一服务端实现。执行与完整记录在 Scout；Nexus 持有任务、准入、资源租约和结果索引。Nexus 与 Scout 使用 `script.submit` / `record.*` 契约，字段详见 [协议](../接口/协议.md)。

## 提交与执行

1. `case_run` 根据已认证用户确认项目、应用、仓库、设备归属和占用；记录请求的完整用例清单、提交版本、环境和设备。
2. Nexus 持久保存任务及每条执行的派发记录，再返回任务 ID 和 `report_url`。每条用例有独立的 `session_id` / `attempt_id`；网络重投保留 ID，显式重跑创建新 ID。
3. 调度器发送 `script.submit`。Scout 必须先将 attempt 落在本机，再回复接单摘要。传输层 `PASS` 和 `state=accepted` 只表示接单，不代表测试通过。
4. Scout 使用独立执行进程把 Git 副本保存在执行工作区 task_id/attempt 的 source 下，输出写入同 attempt 的 output，解析配置和页面，核实租约，执行项目/用例前后置及 `run(case)`。任务超时预算独立于提交请求的短 ACK 预算。
5. 详细步骤、界面结构、截图、断言、源用例快照与诊断留在 Scout。账号请求仍经 Nexus 账号池处理；完整设备证据不回写 Nexus。
6. Scout 的持久 outbox 发送 `record.sync` 摘要。Nexus 校验已准入节点、用户、任务、用例和 attempt，按 `summary_version` 幂等更新索引；持久成功后才 ACK。较旧摘要不能覆盖新摘要，已完成执行不能被改回 running。

以上是 `record_api_version=1` 节点的完整执行契约。Python 暂保留旧节点的 `script.run` 同步兼容分支，旧记录沿用原来源，不标记为 Scout 本地记录；未声明记录能力的节点返回 `record_api_required` 并要求升级。旧兼容路径的存在不代表已经支持完整新闭环；可靠异步派发与本地证据读取需要配套升级 Nexus 和 Scout。

## 持久调度与恢复

Nexus 使用 SQLite 持久派发记录及后台对账线程，业务状态不依赖请求线程或仅存在于内存的 RPC Promise。节点注册会唤醒调度，后台对账也会发现创建请求中断后遗留的记录。不同任务公平取最早未完成用例，同一批次顺序执行，并保留执行账号身份。

| 场景 | 处理 |
|---|---|
| 提交 ACK 丢失 | 先查询相同 attempt；确认不存在时才重投完全相同的提交 |
| 接单后节点重连 | 查询记录状态；不生成第二次执行 |
| 终态上报 ACK 丢失 | Scout outbox 重发摘要，Nexus 回已持久化的版本 |
| Nexus 重启 | 从持久派发记录恢复，继续查询和补发短指令 |
| Scout 执行进程中断 | 标记 interrupted / blocked，保留真实记录，不盲目重放最后动作 |
| 节点离线或结果未知 | 标记待核实并保持资源隔离；在线标志或租约时间经过本身不能证明旧任务停止 |

## 取消与资源

`POST /case-runner/tasks/{task_id}/cancel` 先持久保存取消意图。未下发用例可以直接收口为 cancelled；已下发用例通过 `record.cancel` 请求 Scout 停止。`cancel_requested` 不等于已取消。

Scout 确认停止后仍可能报告 `resource_isolated=true` 或 `execution_started=unknown`：这表示最后一次设备动作结果尚不确定。即使 status 为 cancelled，也不能自动释放设备和账号。

设备租约由 Nexus 原子认领。Python 使用持久资源账本的 attempt / epoch 核对持有者。Web 按四个槽位分别认领，其他设备独占。`script.lease` 必须校验实际持有者；提供租约标识时 Scout 不接受不匹配的代次。`device_list.executable` 必须同时考虑在线、就绪、归属、兼容性、占用和隔离。

账号 `case.nexus.account(requirements, *, slot="default", app_id=None, platform=None)` 支持同一脚本按用途租任意多个账号。`slot` 是幂等键；不同 slot 可跨应用、跨平台，并使用各自的 app/env/surface 登录与 OTP 策略。同一 slot 改变 scope 返回 `account_slot_scope_mismatch`；租约失效返回 `resource_account_missing`，不得换号重试。跨项目应用、不支持平台和无法唯一确定的渠道均阻塞。`all` / `prefer` 条件、项目/用户/环境/健康/占用约束仍适用；动态业务标签只用于排序，不因标签未知伪称前置不满足，也不因选中账号就宣称前置已经证实。真实前置仍由 Scout 执行与断言验证。

应用默认渠道在配置读写时保留；准入选定的平台、渠道和目标标识按设备保存到 `device_targets`。混合批次的 `mixed` 只用于展示，准入、资源认领和脚本派发使用每台设备的目标。任务选定的 `env_profile` 和 `env_surface` 在恢复账号租约前绑定到执行上下文，并保存到持久派发记录。重启恢复沿用该渠道；旧派发记录缺渠道字段时，从同一用户的原任务补齐。选号使用显式渠道并校验平台，不按 URL 重新推断或切换到同地址的其他渠道。

Nexus 回调拒绝时，Scout 保留 `nexus_rejected` 分类，摘要优先使用 Nexus 的具体拒绝信息。完整 `run/finished` 事件另存 `nexus_error`（能力、操作、上游错误代码），不保存回调参数或账号凭据；`ValueError` 等异常类型不能遮盖具体原因。

## 索引与证据读取

`agent_guide.workbench.connection_status=not_checked` 表示入口未做连通性检测；`login_failure_message` 只规定实际登录失败时的提示文案，不能作为当前连接故障。`configuration_status` 与入口 URL 单独描述配置是否可用。

Nexus 保存每例状态、简短原因、耗时、记录归属、摘要版本、证据水位、断言计数和来源覆盖摘要。完整事件和图片由 Scout 保存。

| 对外接口 | 来源 |
|---|---|
| `GET /case-runner/tasks`、`/tasks/{task_id}` | Nexus 索引，Scout 离线仍可查看 |
| `GET /case-runner/sessions` | Nexus 记录索引 |
| `GET /case-runner/sessions/{session_id}/record` | 经已认证长连接查询 Scout 摘要 |
| `GET .../{session_id}/events?from_seq=N&limit=100` | `record.events`；`from_seq` 排他，下一页传 `next_seq` |
| `GET .../{session_id}/artifacts/{artifact_id}` | `record.artifact`；有界读取，支持 HTTP Range |
| `GET .../{session_id}/artifacts/{artifact_id}/chunk?offset=0&length=32768` | 最多 65536 字节一块，返回 base64 与范围信息；完整 UTF-8 且序列化不超过 96 KB 时附 text |
| MCP `session_events` / `session_artifact` / `session_screenshot` | 共用同一记录服务；events 字节预算默认且最大 196608，大节点通过 artifact 分块读取；截图工具读取已存图片 |

记录读取先校验用户对持久索引的归属，再由 Nexus 填入可信 owner 和节点，不接受客户端本机路径。Scout 离线返回 `evidence_temporarily_unavailable`；记录不存在、artifact 过期分别明确返回失败，不能返回空数组伪装成功。

截图按需读取，不把大段 base64 放入任务 JSON。浏览器通过已认证请求读取 blob；不把访问凭据拼进图片 URL。每次节点 artifact RPC 限定大小，流式代理使用背压并支持取消。

## 上线与验证

升级时先完成 Nexus SQLite additive migration，再发布 Nexus 与支持记录 API 的 Scout。版本发布与生产迁移需要按部署流程执行，源码修改不等于线上已生效。

最低验证包括：人工用例一条完整通过、失败断言、超过 30 秒的任务、重复提交、ACK 丢失、重连、取消确认、未知写结果保留隔离、跨账号拒绝、原始事件分页与截图读取。模拟 Scout 的协议验证不能冒充真机通过。


## 资源结算补偿与 Web 隔离退出

终态投影不是单独的释放依据。调度器检查持久派发摘要、封存及未知写状态，在事务内释放设备、账号和准入；后台按持久索引补齐投影及遗留释放。从未派发的取消可直接结算；已派发未知动作继续隔离。

Web 已结束任务的 owner 可显式核验 `record.resource_status` 并调用 `/tasks/{task_id}/resources/reconcile`。停止与浏览器关闭证据、记录版本及租约代次一致时，保存独立恢复决定并一次释放所有资源；原 Scout 结论不改。实体设备继续使用基线恢复入口。Scout 需支持新停止证明。Workbench 提供“核验并释放资源”，MCP 提供 `task_resource_reconcile`。


## 本机编写调试

`debug_case` 直接绑定本机编写目录，不拉仓、不要求 commit；远端 Scout 仅用于正式执行。Nexus 复用正式任务的持久准入、租约与证据索引，但 execution_kind=debug 在 Scout 启动持续 worker，每段刷新 pages/flows；代码片段保留现场，传 `script_path` 的整份脚本复用正式执行的原文绑定、项目/用例前后置和覆盖检查。用例后置失败仍尝试项目后置，各清理异常留证且不覆盖原始失败。会话无总截止时间；片段有独立超时与取消。普通错误后可继续，未知写停止后保留只读核验。结束仍由 Scout 确认进程/浏览器停止后结算。调试归 authoring，不计正式通过率。接口、工作区和版本字段见协议“本机编写调试与执行工作区”。

## 执行契约检查

`python -B tools/check_execution_contracts.py` 在隔离临时目录检查默认渠道、多平台目标冻结、恢复读取、明确的不兼容渠道拒绝、blocked 统计、多账号 slot 幂等与 scope 校验、全量续租及按 slot OTP 策略，纳入 CI。它不连接设备或业务数据库，不替代 Scout 的真实产品验证。
