# 系统架构

Mino 由三个仓库组成。**Nexus 是唯一服务端，Scout 是设备执行节点，Workbench 是唯一前端（编译进 Nexus wheel，不独立部署）。**

```
        ┌──────────────┐
        │  Workbench   │  浏览器，同源 :50104
        └──────┬───────┘
               │ HTTP /ws
        ┌──────▼─────────────────────────┐
        │           MinoNexus            │
        │  准入 · 会话 · 协议 · 数据      │
        │  项目仓库地址 · 租约 · 事件账本   │
        └──────┬─────────────────────────┘
               │ WS /node（Scout 主动 dial）
        ┌──────▼───────┐        ┌──────────────────┐
        │  MinoScout   │───────►│ adb / WDA /      │
        │  拉仓库·跑脚本│        │ Playwright / AX  │
        └──────────────┘        └──────────────────┘
```

## 1. 三端职责

| 仓库 | 职责 | 明确不做 |
|---|---|---|
| **MinoNexus** | 数据归属方：项目 / 用例 / 设备 / 账号 / 任务 / 会话事件 / 能力目录；开跑准入、下发脚本地址、保存回调结果 | 不碰设备（不 import adb / uiautomator2 / playwright / wda / pywinauto，不 subprocess 调 adb）；不做图像算法（不 import torch / open_clip / paddleocr / ultralytics / cv2，唯一例外 `pillow` 做缩略图重采样）；不做逐步决策 |
| **MinoScout** | 拉取脚本仓库、在设备上执行脚本、本机解析验证码、本机调模型 | 不碰数据库、不存业务数据、不读能力目录、不 import Nexus |
| **MinoWorkbench** | 唯一前端：测试工作台 + 管理后台 | 不发现 Nexus（origin 编译进前端）；不做第二套执行视图 |

**一次运行的边界**：`case_run` 由 Nexus 准入 → 下发 `script.run` 载荷（仓库地址 / 提交 / 脚本路径 / 设备 / 平台）→ Scout 自己 `git clone` 并执行 `run(case)` → 账号、步骤、失败、证据通过 `script.callback` 回 Nexus 写入 `session_events`。**Nexus 不读、不打包脚本仓库，也不决定下一步点哪里。**

## 2. 代码分层

18 个包，**只允许 import 层号更小的包**，由 `python3 tools/arch_report.py --check` 强制（CI 中执行）。该脚本会扫描**函数体内的 import**——本仓 3,279 处 import 在函数体内，只扫模块顶层会漏掉约 80% 的真实依赖。

| 层 | 包 | 放什么 |
|---:|---|---|
| 0 | `core/` `contract/` `models/` | 基础设施、纯数据契约、ORM。`core/paths.py` 与 engine 分开，避免拼路径就要 import ORM |
| 1 | `records/` | 事件账本（原子写 / writer / 绑定） |
| 2 | `platform/` | 身份、凭证、节点、设置、迁移、集成插件 |
| 3 | `resources/` | 设备、账号、项目环境、资源池、文档库、节点登记 |
| 4 | `catalog/` | 能力目录 loader / registry（读 `catalog_entries`） |
| 5 | `knowledge/` | 政策、文档检索、意图面、检查口径 |
| 6 | `runtime/` | `run_context` · 菜单 · 会话闸门 · cursor 状态 |
| 7 | `navigation/` | 图谱（atlas）· 几何与控件定位 · 登录链 |
| 8 | `action_space/` `ai/` | 动作载荷组装 / 坐标参数 · planner / prompt 渲染 / LLM 客户端 |
| 9 | `casework/` | 用例 / 评审 / QA / 工作区 / 平台迁移 |
| 10 | `assistant/` | 对话 / 通知 / 媒体 / 网关 / IM 连接器 |
| 11 | `loop/` | `case_runner` · `script_dispatch` · `script_callback` · `router_proxy` |
| 12 | `api/` | HTTP 路由（`r*.py`），WS：`ws/observers.py`（UI）/ `ws/node.py`（Scout） |
| 13 | `<root>` | `app.py` / `cli.py` 装配根，只 import `api` |

`prompts/` 是数据目录，不是代码包（启动时解析、校验，格式错拒绝启动）。

**命名约定**：路由用 `r*`，WebSocket handler 用 `w*`，沿用上游 MiniOrangeServer 命名。ORM 一张表一个文件（`models/*.py`），表结构见 [数据模型](../架构/数据模型.md)。

## 3. 装配根的两个坑

都会让服务**静默失效**，改 `app.py` 前必看。

### 3.1 请求模型 / WebSocket 注解必须在模块级

`app.py` 与 `api/ws/node.py` 有 `from __future__ import annotations`，函数注解是字符串，FastAPI 拿模块 globals 去 `eval`。定义在函数体内的 `BaseModel` 子类或 `WebSocket` import 拿不到 → `NameError` → 整个 app 起不来。

### 3.2 fastapi 版本上界是必须的

fastapi 0.141.1 起，`include_router(APIRouter(prefix=...))` 会把路由路径解析成空串，12 个 router 全部静默失效，而 `app` 照常启动、`/health` 照常 200。`pyproject.toml` 钉 `fastapi>=0.124,<0.130`。
