# 凭据存储边界

本文只说明**测试资源账号池中的 `password` / `otp`**。飞书 CLI、SMB、AI Provider、Scout Gmail、插件密钥等不属于业务测试账号，继续按各自现有的本地或系统配置边界保存。

## 结论

- **Nexus 是业务测试账号的唯一事实源。** 账号资料通过 `/project/{project_id}/accounts` 维护，执行时由 Nexus 租约把本次所需字段交给 Scout。
- Workbench 是纯 Web 应用，不依赖 Electron、macOS Keychain 或浏览器钥匙串。表单值只在页面内存和 HTTPS 请求中短暂存在，不写入 `localStorage`、`IndexedDB` 或 Service Worker。
- 账号列表读取的是账号表元数据和 `has_password` / `has_otp` 配置状态；编辑时提交新值。普通列表、详情、MCP、模型上下文、日志、导入预览和证据快照都不回显旧密码或 OTP。
- 当前 Nexus 是单机 SQLite 服务。`password` / `otp` 的 AES-256-GCM 字段加密是已有的数据库静态保护实现，不是必须继续扩张的凭据平台。
- **本轮不建设 KMS、per-project DEK、第二套账号表或多 Nexus 集群。** 这些能力不阻塞内部测试账号的表格化维护与执行租用；未来确有多实例需求时再单独设计。

## 1. 信任边界

| 位置 | 持久化凭据 | 可见内容 | 约束 |
| --- | --- | --- | --- |
| Workbench 浏览器 | 否 | 用户正在填写或替换的表单值 | 必须使用 HTTPS；不得记录请求体或写入浏览器存储 |
| Nexus API 进程 | 仅进程内存 | 请求字段、当前租约账号所需字段 | 完成身份、项目、应用范围和租约校验后才解密；不得写普通日志 |
| Nexus 数据库 | 仅密文 | `enc:v1:...` | 数据库备份不能单独恢复出明文 |
| 主密钥存储 | 是，且独立于数据库 | AES-256 密钥 | 不得打进镜像、仓库或 `mino.db` |
| MCP / 模型 | 否 | 配置状态和脱敏元数据 | 不提供旧密码或 OTP 明文回读 |
| Scout / 执行通道 | 否 | 当前租约账号本次所需字段 | 必须校验租约、应用范围和通道身份 |
| 运维审计 | 否 | 账号读取、预留、释放、更新事件 | 审计记录不得包含凭据值 |

字段级加密只降低数据库文件、备份或 SQL 查询泄露后直接看到密码的风险，不能替代 HTTPS、访问控制、日志脱敏和终端安全。

## 2. 账号维护入口

业务测试账号统一走 Nexus 号池，不新增仓库密码文件、Keychain 条目或旁路表格：

- `GET /project/{project_id}/accounts`：读取账号表、应用范围、环境、标签和凭据配置状态。
- `POST /project/{project_id}/accounts`：新增账号；`app_ids` 必填且必须属于当前项目。
- `PATCH /project/{project_id}/accounts/{account_id}`：修改指定账号；只更新传入字段。
- `DELETE /project/{project_id}/accounts/{account_id}`：删除空闲账号；存在租约时拒绝。
- `POST /project/{project_id}/accounts/import/...`：批量预览和导入；凭据字段只允许写入，预览与结果不回显值。

Agent 和 MCP 使用 `resource_account_list`、`resource_account_create`、`resource_account_update`、`resource_account_delete`、`resource_account_import` 完成选号及元数据维护。脚本不自行连接数据库，也不从本机钥匙串、聊天记录或环境变量寻找业务测试账号。

账号必须显式绑定一个或多个应用：

- 新账号默认勾选当前应用，不提供“全部应用”语义。
- `app_ids` 去重、至少一项、最多 100 项，且必须属于当前项目。
- 已有账号存在未释放租约时不能改应用范围或删除。
- 历史 `app_ids=[]` 表示未关联应用，不参与选号和租约领取。
- 列表、详情、OTP、预约、候选排序、模板分配、恢复和实际租约领取都要求显式 `app_id` 并校验范围。

## 3. 当前加密实现

### 3.1 算法与格式

- 算法：AES-256-GCM。
- 每个字段使用独立随机 12 字节 nonce。
- 密文格式：`enc:v1:<key_version>:<base64url(nonce+ciphertext)>`。
- AAD 绑定 `project_id`、`account_id`、字段名、密钥版本和 schema 版本。复制密文到其他项目、账号或字段后无法正常解密。

当前 keyring 是部署级全局 keyring，支持一个 active key 和多个历史版本；不包含 KMS envelope encryption 或按项目撤销密钥。

### 3.2 密钥来源

以下来源互斥，不能同时配置：

| 环境变量 | 用途 |
| --- | --- |
| `MINO_NEXUS_CREDENTIAL_MASTER_KEY` | 直接提供 base64url 编码的 32 字节密钥 |
| `MINO_NEXUS_CREDENTIAL_MASTER_KEY_FILE` | 从文件读取密钥；拒绝符号链接和 group/world 可读文件 |
| `MINO_NEXUS_CREDENTIAL_KEYS_JSON` | 多版本 keyring，JSON 对象为 `{版本: base64url 密钥}` |
| `MINO_NEXUS_CREDENTIAL_KEY_VERSION` | 指定 active key version，默认 `1` |

开发模式在未配置显式密钥时，会生成 `<data_dir>/secrets/credential-master.key`，目录权限为 `0700`，文件权限为 `0600`。生产模式缺少密钥时拒绝启动凭据读写，不会静默生成新密钥。该文件是 Nexus 数据目录中的部署配置，不使用 macOS Keychain。

### 3.3 明文生命周期

1. Workbench 在内存中收集新值，通过 HTTPS 提交。
2. Nexus 完成身份、项目和字段校验。
3. 写库前在进程内存中加密，数据库只收到密文。
4. 列表和详情只返回 `has_password` / `has_otp`。
5. 自动执行只有账号存在有效租约、应用范围匹配且执行通道经过认证时，才为本次租约按字段解密；人工 OTP 查询要求项目维护权限并显式传入 `app_id`。

### 3.4 兼容与迁移

- 新写入统一为密文。
- 历史明文只读兼容，迁移完成后重新加密。
- 既有密文、key version 和迁移工具保留，不因简化产品范围而删除。
- 凭据格式、导入预览、日志和证据快照都有脱敏检查。

## 4. 本地专属配置

以下配置不进入 Nexus 业务测试账号池，也不需要为了本文改成统一凭据系统：

- 飞书 CLI 的本地登录状态与机器配置。
- SMB、本机目录和运行环境凭据。
- AI Provider 与 Scout Gmail 的节点本地配置。
- 插件密钥和节点级渠道配置。

这些配置由对应工具或节点负责，Agent 不应从 macOS Keychain 读取业务测试账号来替代 Nexus 号池。

## 5. 当前不做的事

- 不新增仓库账号密码表，也不把 Nexus 号池复制到脚本仓库。
- 不新增第二套凭据数据库或旁路密钥服务。
- 不建设 KMS、Secret Manager、per-project DEK、项目级密钥撤销和自动轮换控制面。
- 不建设多 Nexus 实例、负载均衡、HA 或跨实例分布式锁。
- 不为了未来多机目标阻塞当前账号表维护、租约和执行链。
