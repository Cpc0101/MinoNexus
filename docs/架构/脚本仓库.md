# 脚本仓库与页面

一个项目对应一个脚本仓库（`project_script_repos`）。用例的业务顺序写在 `tests/`，页面与定位写在 `pages/`，公共业务函数在 `scripts/`。

```
pretest.py                     # 整个项目的前置（已有才改）
posttest.py                    # 整个项目的后置（finally 执行）
config.yaml                    # apps：应用 key → 各环境地址
scripts/
  login.py                     # 多条用例复用的业务函数
tests/
  账号/
    case07fffa13.py            # 一个 case_id 一个文件，全渠道只此一份
pages/
  camera/                      # 目录名 = config.yaml 里的 app key
    splash.yaml                # 文件名 = page_key
    home.yaml
```

## 1. 三个目录各写什么

| 目录 | 谁写 | 里面有什么 | 里面**没有**什么 |
|---|---|---|---|
| `tests/` | 用例业务顺序 | `run(case)`、步骤编号、调用 `scripts/` 与 `case.*` | 平台后缀（不写 `case07fffa13.android.py`）、`if platform`、控件定位 |
| `scripts/` | 多条用例共用的业务 | 登录填表、进入某页后的业务动作 | 渠道选择器、页面锚点 |
| `pages/` | 应用逻辑 | 页面身份、锚点、控件、各渠道定位、入口 | 账号密码、访问次数、评审结论、可执行代码 |

`flows/` 与 `scripts/` 同性质（业务函数，接收 `app`），保留兼容。

## 2. `config.yaml`

仓库根，顶层只有 `apps`。key 必须匹配 `^[A-Za-z][A-Za-z0-9_]{0,31}$`，它同时是脚本里 `case.config.<KEY>` 的名字和 `pages/<KEY>/` 的目录名。

```yaml
apps:
  camera:
    app_id: app-xxxx                # Nexus 应用 id
    platform: android
    package: com.example.camera     # 身份字段：package / bundle_id / url 三选一
    envs:                           # 按环境覆盖身份字段
      dev: { package: com.example.camera.dev }
      prod: { url: "https://camera.example.com" }
```

身份字段只允许 `package` / `bundle_id` / `url`。含 password / token / otp / secret / key 等敏感键名一律拒绝。

**改了 `config.yaml` 并 push 后，必须调 MCP `repo_apps_sync` 告知 Nexus**（或用 `PUT /project/{project_id}/repo-apps`）。Nexus 不读仓库，不自动感知。`repo_apps_get` 可回看 Nexus 侧当前清单。约束：合并后 ≤32 个应用；同一个 key 不能在 `apps` 和 `remove` 里同时出现。

## 3. 页面文件

一个 `page_key` 一个 YAML，**放在 `pages/<APP_KEY>/` 下**（目录名必须等于 `config.yaml` 的 key，直接放 `pages/` 根下会被 Scout 拒绝：`页面文件要放在 pages/<APP_KEY>/ 下`）。

```yaml
page_key: login
label: 登录
states:
  - id: default
    anchors: ["登录", "注册"]
controls:
  - id: submit
    label: 登录
    locator_spec:
      uiautomator: {cardinality: one, selector: {kind: text, value: "登录", exact: true}}
      xcuitest:    {cardinality: one, selector: {kind: label, value: "登录", exact: true}}
      playwright:  {cardinality: one, selector: {kind: role, name: "button", value: "登录"}}
entries:
  - from: welcome
    trigger: 打开登录
    platforms: [android, ios, web]
```

`locator_spec` 的单元格名固定：`uiautomator`（android）、`xcuitest`（ios）、`playwright`（web）、`ax`（mac）、`uia`（win）。某渠道没有单元格 → 该渠道跑到这个控件时失败，`locator_missing`，**不改用另一渠道的定位，也不另写一份用例脚本**。

不放进 YAML 的运行数据：`visit_count`、用例引用数、截图、评审批准状态。引用由「哪些 `tests/` 提到这个 `page_key`」算，访问次数从 `session_events` 算。

## 4. 用例怎么写

```python
# scripts/login.py
def fill(case):
    case.on_page("login")
    account = case.account()
    case.input("login.email", account["email"])
    case.input("login.password", account["password"])
    case.tap("login.submit")
```

```python
# tests/账号/case07fffa13.py
from scripts.login import fill

def run(case):
    case.launch()
    with case.do(1):
        fill(case)
    with case.check(1):
        case.on_page("home")
```

规则：

1. 一条用例一个文件，业务从 `scripts/` 来，定位从 `pages/` 来。
2. 脚本里不写平台判断。渠道差异只改 `pages/` 里对应单元格。
3. 控件写 `page_key.control_id`（如 `login.submit`）；`case.on_page("login")` 之后可以只写 `submit`。
4. 页面文件里没有的控件不要点，不要用整屏搜索文案绕过。
5. 坐标不写在用例里。某渠道只能按坐标点时，写进该渠道的 `locator_spec`。
6. 重复三次以上的业务收成 `scripts/` 的函数。
7. 断言用 `case.on_page` 或 `case.vlm`。`verdict="pass"` 未通过会中止。

## 5. `case.*` 指令

设备、账号、模型都走 `case.*`。**脚本里禁止 `import` adb / uiautomator2 / playwright / facebook-wda / appium / selenium，禁止 `subprocess`**——Scout 的脚本运行时有一份禁用模块名单，命中直接失败。

| 调用 | 执行位置 | 作用 |
|---|---|---|
| `case.launch()` / `close()` / `kill()` | Scout | 启动 / 关闭 / 强杀当前应用 |
| `case.on_page(page_key)` | Scout | 用页面文件里当前渠道的锚点核对界面，对不上就失败 |
| `case.tap(control)` / `tap_xy(x, y)` | Scout | 按控件 id / label 点击；坐标点仅用于页面文件已声明坐标的情况 |
| `case.input(control, text)` | Scout | 向控件输入 |
| `case.swipe("up")` / `back()` / `press(key)` | Scout | 方向 up/down/left/right；返回；按键 |
| `case.wait(ms)` / `screenshot()` / `hierarchy()` / `sample(ms)` | Scout | 等待、截图、读结构、按间隔连拍（不调模型） |
| `case.vlm(问题, verdict="pass")` / `vlm_frame(序号, 问题)` | Scout 本机 | 看最近截图 / 看指定帧 |
| `case.llm(问题)` | Scout 本机 | 文本模型（不要用它决定下一步点哪里） |
| `case.account()` | Nexus | 本次租到的账号 |
| `case.scout.otp(account)` / `otp_mail()` | Scout 本机 | 按登录策略取码：账号自带码 → 固定码 → Gmail |
| `case.note(文本)` | Nexus | 只记证据，不操作设备 |
| `case.fail(原因)` | Nexus | 判定失败并停止 |
| `with case.do(n)` / `with case.check(n)` | Nexus | 写 `node/enter` / `node/leave` |

`case.event` **已删除**。业务差异写成 `scripts/` 里的函数。

## 6. 下发时带上哪些文件

Nexus **不打包**。Scout 自己 clone 仓库后读 `config.yaml`、`pages/<APP_KEY>/*.yaml`、`scripts/`、`flows/`、目标 `tests/**/<case_id>.py`。仍禁止 `..` 和绝对路径；YAML 只解析，不当代码执行。

## 7. 自检

写完后在仓库根运行 `mino-scout check .`，只给提示，**执行时 Scout 不做任何预检**。
