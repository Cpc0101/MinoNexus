# Python 打包与历史入口边界

Nexus 0.1.90 修复发布检查发现的 20 处延迟导入错误。根因是旧编译器、前置计划生成器和 IM 接管收件箱删除后，消费者仍引用原模块。

- 历史用例列表保留已存步骤与预期的纯格式化读取，读取计划不加载编译器；历史编译摘要不宣称当前脚本可执行。
- 编译指标、页面步骤键绑定、复检／重编译和导入预览编译重试入口返回 HTTP 410。
- 历史 pending 编译预览标记为错误并明确 `case_compilation_removed`，不继续启动后台编译，也不伪装完成。
- 前置计划兼容入口只允许读取已捕获的计划，尝试重新生成时明确拒绝；设备准备仍由 Scout 脚本负责。
- 删除无法从公开入口到达的旧 IM 收件箱处理函数，不恢复已下线的 IM 收发及接管。

发布门禁依次检查分层、延迟导入、未定义全局名、调用签名和返回路径，再构建 wheel。隔离验证使用临时数据目录，不读写共享业务库，不运行 pytest。

同版包含账号 `app_ids` 生效范围：SQLite schema 13 为旧账号追加默认空列表（项目通用），追加前保留一致备份。保存、候选筛选和实际领取均核验范围；范围变更与占号竞争需要原子比较，不根据候选筛选结果直接宣布领取成功。

五项 Python 构建门禁通过。wheel 与 sdist 在隔离构建环境生成，临时安装 wheel 后再次核验全量延迟导入及应用路由装配。临时回归覆盖退役接口 410、历史用例显示、不修改已存计划、pending 预览不伪装成功，以及前置计划生成拒绝。

## Scout 静态下载分发

Scout 主分支的原生打包全部成功后，在 Scout 仓库运行 `Publish verified native artifacts`，`run_id` 指向该次主分支打包。正式 tag 发布完成后，在 Nexus 仓库运行 `Publish Scout distribution`，传入相同 `release_tag`。该流程复用部署 SSH 身份和固定主机指纹，无需把服务器密钥复制到 Scout 仓库。

`scripts/publish-scout-release.py` 先验证官方清单的版本、源码 SHA、build_id、三平台、应用与运行时/浏览器层依赖及所有 ZIP 的长度与 SHA256，然后发布不可变版本目录。已发布的版本不可更换 build_id，禁止降级；校验完成才原子切换根清单，入口 bootstrap 同步更新。可重复运行同一版本。下载、校验或传输失败不会提前更新根清单，失败的 incoming 目录保留供排查。

部署后核对公开清单版本和 build_id，再通过 MCP `scout_release_meta` 验证 Nexus 返回的安装版本；不能只凭 GitHub 最新 tag 或清单地址返回 200 宣称分发已更新。

公网 TLS 入口需从外部验证。2026-11-19 的排查确认 443 在公网被重置而已配置的 8443 可达；新的 Scout 分发清单使用 8443 资产地址。服务器 localhost 健康检查成功不能替代公网可达性；`continue-on-error` 的公网检查失败也不能写成“所有部署检查通过”。

Agent workflow 初始化的 `scope` 是业务入参，转发层必须保留；不能沿用旧 case-selection 范围过滤而将它丢弃。
