# 本机调试会话验证

## 实现边界

Agent 与 Scout 在同一台机器编写和调试。`debug_case` 绑定已有编写工作区，显式指定本机节点和设备；不拉仓、不要求 commit、不提供跨机文件同步。远端 Scout 用于正式 `case_run`。

调试持续保留执行进程、设备和应用状态，每次片段捕获 Python / YAML 文件版本并刷新 pages/flows；生成文件、事件与截图进入任务执行工作区。正式执行在独立 task/attempt 下保存固定 Git 源码与 output。路径和协议见 [协议](../接口/协议.md)，流程见 [执行链](../架构/执行链.md)。

## 配套部署后的验收

1. 本机启动调试会话，分段操作到真实结算页，让一处定位失败。
2. 确认失败后设备仍独占、页面保留；读取同一会话的截图和控件树。
3. 在编写目录修正 pages，使用新请求 ID 重跑该片段，验证唯一定位、操作后的页面变化及完整业务断言。
4. 核对新片段版本、动作顺序及证据；历史版本的局部成功不能替代新版本验证。
5. 结束会话，等待 Scout 停止证明与资源结算；固定完整用例版本。
6. 用 `case_run` 从明确初始状态独立跑通，核对正式断言和通过率，确认未带入调试状态。

还需在真实渠道验证执行中断线、不可协作取消及未知写隔离；仅收到结束 ACK 不得认定资源已释放。当前没有进行部署、安装更新或上述真机验收。
