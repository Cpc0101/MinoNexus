# 本机测试资产

## 数据边界

同一份生成结果有三种状态，目录不能混用：

| 状态 | 谁在用 | 文件位置 |
|---|---|---|
| 执行任务时生成 | 当前准备任务 | `~/.mino/scout/accounts/<profile>/workspaces/execution/<task_id>/attempts/<attempt>/output/` |
| 使用之前的 | 之后的 Agent，只持有引用 | `~/.mino/scout/assets/<账号>/library/<sha256>` |
| 用例执行时 | 当前正式用例 | 本次 `output/.assets/<asset_id>/v<version>/` |

`publish` 只接受当前任务 output 里的文件，并复制进库。`fetch` 只在用例执行时从库复制到本次 `.assets`。旧任务的 output 不是后来用例的输入。

Nexus 持有 `asset_storages`（项目配额）、`asset_blobs`（内容哈希/大小/状态）、`test_assets`（不可变逻辑版本）、`asset_preparations`（共享准备及尝试历史）。没有文件字段、上传正文、Base64、公开文件路由或下载代理。可复用正文在发布它的 Scout 库里。

一个项目的内容按 SHA-256 去重，登记即预占目录容量。生成资源长期保留，任务清理不删除它们，Scout 也不为了腾配额删除库内文件。文件引用是 `{asset_id,version}`。`source.node_id` 是持有该文件的 Scout。另一台电脑没有这份字节；派到别的节点会在准入被拒绝。文件元数据每项上限 8 KiB；列表每页最多100。

## 存储位置

Workbench 项目 → 测试资源 → 文件资产 → 本机配额。仅项目所有者能改配额和准备次数；项目成员可查看目录并复制引用。不配置对象存储，不保存密钥，工作台不提供下载。首次登记若尚未配置，使用 50 GiB 目录额度和 512 MiB 单文件上限，准备次数为 0。

- Scout 先把文件提交进本机库并校验 SHA-256，再向 Nexus 登记 ready。登记失败时库文件和待登记记录都留着，下一次 `flush` 只重试登记。
- 当前单文件最大 512 MiB。没有分片上传，也没有跨节点传输。
- 当前无自动删除已登记文件。直接删掉库文件后，原用例校验失败，不会因此判通过。

## API

统一前缀 `/project/{project_id}/assets`，均需认证项目权限。

| 方法与路径 | 内容 |
|---|---|
| GET/PUT `/storage` | 本机库配额与准备次数；不接受地址、桶或密钥 |
| GET 空路径 | 分页目录 kind/state/limit/offset |
| POST `/uploads` | 固定 asset_id/version/kind/title/filename/attributes/source、sha256/md5/size_bytes；登记 ready 引用，不返回传输地址 |
| POST `/{asset_id}/{version}/upload-ticket` | 已登记引用，不重新生成文件 |
| POST `/{asset_id}/{version}/complete` | 读取已登记引用 |
| POST `/{asset_id}/{version}/download-ticket` | 读取已登记引用；Scout 再用哈希打开本机库 |
| GET/POST `/preparations` | 准备目录/共享领取；选配方和执行在 Agent/Scout |
| PUT `/preparations/{preparation_id}` | 已验证资产与证据，或已知失败；记录尝试历史 |

`resource_asset_list`、`resource_asset_prepare`、`resource_asset_prepared` 是 MCP 目录/准备入口；MCP 不暴露配置密钥或文件票据。准备需求至少有 app_id/environment/kind/attributes；相同需求与不同配方仍合并在途任务。准备次数预算0默认关闭，所有者一次明确配置后范围内自行准备。准备中的原结果未知保持 wait，不自动重造；failed 后新证据可申请 retry，预算不重置。资源 ready 不代表业务断言通过。

用例执行副本写在本次 attempt 的 output，随该任务记录保留。它不进入可复用库，也不能再次 publish。库文件和未登记原件不被回收。生成任务的 output 仍留在该任务目录。

Scout Case API：`case.assets.publish/find/fetch/require/flush`。引用已注入 inputs 时，派单检查节点声明 `asset.transfer` 且包含 `local_library`，并核对 `source.node_id`。旧节点不接收显式资产引用。脚本直接调用新 API 仍要求升级到支持它的 Scout，不能用包版本猜能力。

## 发布与回滚

1. 先发 Nexus；资产表为 schema15 的增量新表，不变更已有业务表，旧版本容忍新表，回滚保留资产目录。隔离 smoke 验证过从旧表集补表，生产上线前仍应备份数据库。
2. 再发 Scout；库和待登记队列在账号隔离的 `config_dir/assets` 下，生产即 `~/.mino/scout/assets`，与安装目录、Git 工作区独立。升级不清理队列。仅在已停止接单并处理当前任务的节点上升级。
3. Workbench 独立构建发布；不打进 Nexus wheel/镜像。
4. Skill 仓库包含主动准备规则；未自动安装到用户 Skill 目录，发布/安装仍需明确安排。
5. 用同一台 Scout 验登记、校验和再次 fetch，再启用项目准备预算。当前隔离 smoke 不是云端、真机或过夜无人值守验收。换一台电脑不能取得已生成的文件。

验证入口：Nexus `python3 tools/check_asset_store.py`；Scout `python3 scripts/check_asset_cache.py`；Workbench `npm run typecheck` / `npm run build`。不使用 pytest，不访问真实 mino.db。
