# 执行统计与报告口径

2026-11-17 源码完成；尚未部署，未执行真实业务 UI 用例。隔离检查验证统计和记录契约，不代表产品业务通过。

## 统计单位

任务列表、详情、应用摘要和通知共享 `statistics`。真源是 `contract/execution_report.py`。Workbench 使用服务端统计，不按卡片颜色或自由文本推算通过率。

| 字段 | 含义 |
|---|---|
| `execution_units` | 本任务选中的用例执行次数，多设备执行分别计数 |
| `formal` | verification/regression 正式范围 |
| `authoring` | 编写探针，保留自身结果，排除正式统计 |
| `preparation` | source_context.purpose=prepare 的数据准备，排除正式统计 |
| `unclassified` | 已执行但尚未读出用途，不计正式结果 |
| `expectations` | 正式执行中按原文预期聚合的 total/pass/fail/unknown/not_run |
| `assertions` | 正式执行的全部断言数量，包括辅助检查 |
| `auxiliary_assertions` | 未关联原文预期的断言，单列，不能冒充业务预期 |

每个执行分组提供 total/completed/executed/not_run/execution_unknown、passed/failed/blocked/declined/skipped/cancelled/unverified/pending、judged/pass_rate。状态分类之和等于分组 total。completed 表示进入终态，界面称“已结束”；不等于实际执行或业务通过。executed/not_run/execution_unknown 之和等于 total；开始时间、running 状态或实际断言可以证明脚本执行。`execution_started` 是设备写动作回执，no 不能单独证明脚本没有执行。

通过率只用正式 passed / (passed + failed)；无有效判定时为 null。blocked、declined、skipped、cancelled、unverified 分列，不计 failed。原文预期的 not_run 不等于 skipped 用例数。`cases_reported/cases_missing` 表明预期或断言摘要是否覆盖全部正式执行；摘要缺失不补零结论。requested_total 和 skipped_cases 仍表示申请范围及未入选条目，不能和多设备执行次数混算。

任务 `status` 保留调度生命周期；`result_status` 表示正式范围结果。有正式失败为 fail，只有阻塞则 blocked；拒绝与全部跳过分别为 declined/skipped；通过和跳过混合为 unverified；全部正式通过才为 pass。纯探针/准备任务结束为 done，各分组仍保留实际失败和阻塞。取消请求不等于取消完成。准备任务和 resume 新任务独立，`source.parent_task_id` 指向相关任务，后续成功不覆盖旧任务。

## 报告与证据

Scout 从同一次执行事件构造 `test_report`，相同预期存在多个断言时，失败优先于 unknown，unknown 优先于 pass；后续页面成立不能覆盖先前业务失败。摘要添加 `context`（task/session/attempt/case/node/revision/script_path/source_hash）和 `auxiliary_assertions`。准备报告用途为 preparation；读取脚本前的未知用途为 unclassified。编写仍使用脚本字面量 RUN_PURPOSE=authoring，正式脚本默认 regression。

接收端校验身份、用途、预期计数、断言计数、事件水位和时间顺序。pass 必须有有效通过断言且不存在失败、unknown、未执行预期或缺失原文覆盖。接单、执行动作、进程结束都不是测试通过。封存后不得改写报告、断言、来源、时间、输出或结论；同版本/旧版本重传幂等，高版本冲突拒绝。对象键的传输顺序不会触发冲突。

任务列表摘要保留执行用途、报告和来源，避免列表再次误算探针。最近正式结果查询先排除探针/准备，再选择最近一次执行；覆盖度只认明确 pass，不能把 completed 当通过。通知使用同一统计函数，并给探针/准备结果加用途标识。

节点离线时，Workbench 展示 Nexus 保存的报告摘要并提示完整证据需从原节点读取；读取一页事件不能当完整报告。旧同步执行路径返回报告和用途，无法对应完整事件编号时使用 event_seq=0，不能伪造可点击证据；模型用量缺失明确标为未报告。没有用途声明的历史记录保持既有用途约定，不从错误文本猜测探针，也不批量修改真实历史库。

## 时间

新任务时间带时区。submitted_at 使用任务创建时间；execution_started_at/execution_finished_at 来自实际执行记录。执行耗时使用本次记录的最早开始到最晚结束；缺少实际执行时间、时区不明确、开始晚于结束或仍在运行时返回 null，并在异常时给 timing.issue。不把接单/同步/任务收口时间补成用例执行时间。Scout 保留毫秒精度，不先按秒取整。任务 finished_at 是调度收口时间，重传不更新它。界面展示日期和时区。
